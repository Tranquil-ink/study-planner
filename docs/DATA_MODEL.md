# 日程看板数据模型

| 表 | 业务内容 |
| --- | --- |
| `planner_categories` | 分类、颜色、归档状态 |
| `planner_projects` | 所属分类、名称、归档状态 |
| `planner_tasks` | 长期任务、所属分类、可选项目、进度单位与总量、激活状态 |
| `planner_todos` | 临时待办、可选分类、可选项目、估时、截止日、激活状态、完成日 |
| `planner_weeks` | 以周一为键，保存七天各三个时段的容量及周初确认时间 |
| `planner_week_items` | 单一任务或待办的周目标，保存计划时长、可选进度新增量及周初目标 |
| `planner_schedules` | 安排日期、早中晚、时段内顺序、对象、计划分钟、可选进度与位置、完成状态 |
| `planner_work_logs` | 实际发生日、对象、可选安排引用、实际分钟、新增量、进度位置和创建顺序 |
| `planner_settings` | 上海业务时区、日期格式与七天各三个时段的默认容量 |
| `planner_dataset_state`、`planner_operation_receipts` | 账号版本、去重请求、实际记录创建顺序 |

每条业务引用含 `owner_id`。项目归属分类须与其成员匹配。每个事项每周最多一个目标。实际记录与关联的安排须指向同一事项。移动只更新日程的日期、时段和顺序，实际按发生日期归周。移除安排或改换关联任务时保留实际，把安排引用清空。

计划时间与实际时间各自持久化。周预算从该周所有安排扣除计划时间，未做也占预算。完成事务可以把到达的累计进度转换为该次实际增量，和日程完成标记、待办完成日期一起保存。尚有旧实际记录的安排完成时可沿用最近一次的记录。精确进度数值用十进制字符串传输，占位说明与章节文字独立保存。

每条周容量或容量模板按周一至周日排序，内层是上午、下午、晚上，单位为整分钟。新的周可沿用默认容量，也可保存本周配置。周初确认一次性保留当前目标的分钟和数量，后续编辑和取消保留历史基线。

所有业务表启用 RLS。前端经 `planner_snapshot` 读取，通过 `planner_mutate` 写入，使用 `planner_receipt` 确认未知的请求结果。事务按账号加锁，校验版本与请求编号。恢复会先校验备份并在事务中替换数据，保留 ID、业务日期、目标基线、卡片顺序和实际记录顺序。

v6 备份包含全部业务数据与设置。阶段 5 的 v5 备份导入时会补齐新字段，并把原日容量与安排归入上午。内部回执、账号凭据和授权数据独立保存在云端。
