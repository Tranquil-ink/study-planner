# 按天安排的数据模型

| 表 | 业务内容 |
| --- | --- |
| `planner_categories` | 任务分类、名称、颜色、归档状态 |
| `planner_projects` | 所属分类、名称、归档状态 |
| `planner_tasks` | 长期任务、分类、可选项目、进度单位与总量、优先级、截止日 |
| `planner_todos` | 一次性待办、分类与项目可空、估时、优先级、截止日、完成日 |
| `planner_weeks` | 每个周一对应一个规划周，保存七天容量及初始确认时间 |
| `planner_week_items` | 单一任务或待办的周目标，含投入分钟、可选新增数量、现行状态及不可覆写的周初目标 |
| `planner_schedules` | 某天的安排、对象、计划分钟和可选计划数量、处理状态。允许多个安排在同一天 |
| `planner_work_logs` | 实际发生日、对象、可选安排引用、实际分钟、新增量、进度位置和稳定创建顺序 |
| `planner_settings` | 上海业务时区、日期格式、可用时间模板 |
| `planner_dataset_state`、`planner_operation_receipts` | 账号版本、去重请求、记录创建顺序 |

每条业务引用包含 `owner_id`。项目归属分类必须与其成员匹配。周目标必须关联一个长期任务或一次性待办，按事项和周唯一。日历和实际记录允许独立事项。关联安排的实际记录与安排须指向同一个事项；计划日期和实际日期可以不同。同一事项的周目标、日历安排和实际记录按事项身份与各自发生周汇总。

进度都用字符串表示非负精确十进制，最多 9 位整数、6 位小数。存在目标量时须大于 0。允许进度为 0 的实际记录。长任务累计的初始量与实际新增量不能超过设定总量。一旦存在实际记录或已分配的数量目标，锁定单位。更改或移除安排时，不会增减实际时长与进度。

保存周初计划时一次性复制当时有效目标的分钟和数量。取消、退回和结转都保留本周历史。计划有初始确认时间后，新增条目没有初始参照。容量模板在首次写入该周目标、日历安排或本周容量时按规则保存到该周，之后可用本周例外覆盖。

所有业务表启用 RLS。应用只由账号所属行的权限读取。事务写入由 `planner_mutate` 完成，以账号为边界序列化，对比 `expectedRevision` 并检查请求编号。前端通过 `planner_snapshot` 读取一致快照，用 `planner_receipt` 确认结果未知的请求。三个入口仅向已登录角色授权。所有的业务表和引用都校验账号归属。

v5 备份包括全部业务数据与设置。恢复保留业务日期、ID、已确认计划和实际记录顺序，重建保存时间和账号版本。事务失败回滚缺失引用、重复 ID 或无效数据。旧格式用对应 Git 版本与同版数据库处理。
