## 1. 手机周二 09:00 → 电脑编辑 → 手机刷新

1. 两端“选择日期”填同一个周二，例如 **2026-10-20**。手机 09:00 点击“安排”。
2. 安排类型选“任务池中的长期任务”，关联“理论力学”，计划学习范围填 `2.1～2.3`，备注写“阅读并做例题”。保存并等待“已保存到云端”。
3. 电脑“获取最新数据”，应在周二 09:00–10:00 看到同一任务、分类色、范围和 **60 分钟**。编辑为 `2.2～2.4` 并保存；手机主动获取后应一致。
4. 电脑在任务池改任务名称或分类颜色，手机刷新，日程应按原任务 ID 显示新名称/颜色，不新增副本。归档任务后既有日程保留。
5. 两端任务初始完成量仍是 **8**、位置仍为 `2.1.1`。本周已排按实际日程相加；周预算“未设置”，实际投入/记录“尚未开放”。
6. 编辑日期/时段，例如移到另一空闲基础时段，保存后旧格释放、新格占用；不得保留两份。日/周切换、翻日/周或切页面不能丢失尚未提交的日程表单。

## 2. 临时报告、时间和导航

1. 手机当天 18:30 新建临时任务“课程报告”，范围“整理提纲”，备注“补齐参考文献”；保存后电脑刷新可见。
2. 时段应为 **18:30–20:15，105 分钟**；另一晚间时段为 **20:15–22:00，105 分钟**。临时报告不进入任务池。
3. 核对每天共 10 个基础时段，午休 **12:00–13:00**、晚饭 **17:00–18:30** 不可安排；全天可放置 690 分钟，界面不将此当作学习目标。
4. 日期选 `2024-02-29`，下一日为 `2024-03-01`；跨年、周日和跨月周显示正确。回到今天以中国日期为准（即使电脑系统时区为 UTC）。
5. 移除报告并等待云端确认；另一端刷新后空格恢复，长期任务与初始量不变。

## 3. 两端竞争同一时段与旧表单

1. 两端先获取同一版本，在同一天同一**空**基础时段分别打开新建表单，填写不同临时标题，再尽量同时保存。
2. **只能一端成功**；另一端提示版本冲突，输入保留。刷新后仅看到一项安排。不能通过确认旧输入覆盖原占用：换另一个空格，或取消新建并明确编辑已有安排。
3. 两端再打开同一既有日程；手机先改范围并保存，电脑旧表单提交必须冲突且保留输入。
4. 电脑获取最新数据后，核对日历及表单，明确点击“已核对，将日程输入应用到最新版本”才能再保存。未确认不能自动提高基础版本。
5. 若手机已移除日程，电脑旧表单先冲突，刷新后应显示日程已移除，禁止重新应用；可复制文字后取消、另建。
6. API 集成脚本另外验证同 revision 并发、已刷新后仍重复占用、直接写表权限、跨账号任务引用；不要仅凭 UI 禁用判定数据库安全通过。

## 4. 断网、未知结果、会话回归

1. 已载入日历后断网，再获取最新数据：报错，原日程保留并提示可能过期，最近成功获取时间不前移，不能显示假空库或误称未登录。
2. 断网前打开日程并填写备注，断网保存：不显示成功，输入保留。若“保存结果待确认”，恢复网络后点击“确认并重试原请求”，不能换新请求盲目新增。
3. 在隔离集成环境模拟数据库已提交但响应丢失，再按同 requestId 确认/重试，应只保留一项日程，revision 不再次增加。手机一般断网不等于此用例，应保存脚本证据。
4. 安卓断网切后台再返回，保留此前已验证的同账号内容与草稿；网络恢复后验证登录并主动取数。真正身份拒绝时停止业务请求、隐藏个人数据，同账号重登后核对原输入/请求；退出则清除草稿。
5. 本阶段本地浏览器回归已覆盖相关分支，但阶段 1 D01～D04 等实机暂缓项**不自动转通过**。只有逐项真实补验后另记日期与证据。

## 5. 完整备份、恢复和 v1 迁移

1. 保留至少一个长期日程和一个临时报告；从数据设置导出完整 JSON。确认 schemaVersion=2，data 有分类、任务（含归档）、设置、全部日程；每条日程有稳定 UUID、业务日期、任务 ID/null、范围/备注、模板版本、slotIds、起止分钟快照。
2. 备份不应含 Auth 密码/token/key、owner_id、内部回执。sourceRevision 仅诊断，不用于覆盖服务器版本。
3. 电脑保持日程旧编辑表单；手机修改或移除日程，再选择先前导出的 JSON。预检显示文件和云端的分类/任务/日程数量，勾选完整替换确认后恢复。电脑刷新应看到恢复后的相同日程与时间；原旧表单不能覆盖恢复结果。
4. 预检后、确认恢复前，让电脑先提交修改，再由手机确认。恢复必须因版本冲突被拒绝，要求重新选择文件预检，不能覆盖电脑新数据。
5. 用备份副本制造相同日期/slot 重复、悬空 taskId、无效日期、错误时间快照或未知版本，预检应拒绝且云端不变。数据库集成脚本直接提交非法恢复，验证插入阶段失败后删除、插入、版本和回执全部回滚。
6. 先保留当前 v2，再选择有效阶段 1 v1 JSON。预览应标明 **v1 → v2，日程 0 项**，明确提醒会移除当前日程；确认后任务 UUID、分类、归档、精确进度、位置与设置保留，日程为空。两端刷新一致。最后可再恢复 v2 找回日程。
7. 损坏/无效 v1 不得作为空数据恢复。约定 v0 格式仍可预检到 v2；真实旧 IndexedDB 迁移仍按阶段 1 的“不适用”记录，不虚构样本。
