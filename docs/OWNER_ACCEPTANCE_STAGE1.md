## 断网读取问题与代码修复

报告现象：手机断网后曾进入登录界面，联网后自动回原页面，云端数据无丢失。报告没有错误码或网络日志，无法断定实机当时的唯一原因。

代码中发现可导致该现象的明确路径：`authService.verify()` 把 getUser 的任何错误都返回为 null，SessionBoundary 又把异常折叠为 null；手机切回前台触发 SDK 的 SIGNED_IN/验证时，连接错误因此被当作未登录。

本次修改：

- Auth 请求失败、超时、5xx/429 保留“暂时无法验证”状态；不据此撤销本页已验证的同账号会话。
- 已加载内容保留并提示可能过期，草稿保留；显示“重试验证登录”，online 事件可重试验证，不后台补传修改。
- 首次打开没有经过服务器验证时，仍不显示个人数据；只显示验证失败与重试入口，不误称账号过期。
- 无会话、明确 401/403/失效凭据和业务 API JWT 拒绝仍要求登录。账号变化会先作废原身份、清除旧视图，不拿缓存或事件里的身份当授权。
- 没有修改数据库结构、RLS、RPC 或备份格式；**不需要重跑建表迁移**。

## 现在只需补做这些步骤

1. 拉取 PR #3 最新分支，保留本机 `.env.local`，执行 `npm ci`、`npm run build`，将新的 `dist` 重新上传到原 HTTPS 测试站点。手机/电脑刷新，必要时清除浏览器的旧静态资源缓存；先保存或取消未提交表单。
2. 手机在线登录并加载任务，打开编辑表单、写一段未提交备注；断网，切到其他应用再返回，点击“获取最新数据”。预期：保留原列表和备注，提示取数/验证连接失败、内容可能过期；不会仅因网络错误转为登录页，最近成功获取时间不前移。联网后点击“重试验证登录”（若出现），再获取最新数据。分别记录直接断网读取和切后台再回前台两种结果。
3. 验证初次加载分支：在线加载过站点后断网，再刷新。如果浏览器能加载前端资源，应显示未完成会话验证而不暴露缓存个人数据；若浏览器本身无法加载网页，记录为未实现离线加载的既定限制，不将其误报为登录过期。
4. 在隔离测试环境验证真正会话失效及重登。访问 token 到期后正常自动续期属于正常行为，不能靠“等待一段时间后仍能用”宣称失效处理通过。先记录联网情况下访问 token 自然过期后的自动续期是否正常；再在受控测试环境使刷新凭据失效并等原访问 token 过期，验证服务器明确拒绝身份时要求重登及草稿保留。只阻断 `/auth/v1/token` 请求会制造刷新连接失败，不等同于服务器判定身份失效；不能据此把真正失效用例标为通过。记录未保存输入、服务器错误码（不含 token）和重登后能否确认原请求。安卓自然过期若仍未执行，继续如实保留未验证。
5. 用原备份的副本分别制造未来 schemaVersion、重复 ID、悬空 categoryId、负数、超总量和未知字段；逐个预检，确认都被拒绝，云端原数据不变。不要修改唯一原备份。另按原清单核对清除一个测试设备网站数据后重新登录取回云端记录。
6. 补填测试实际日期、Supabase 区域、具体设备/浏览器版本；主要触控目标的 44px 指标如没有测量，保留未测记录。若要补集成终端日志，使用新的空隔离测试账号运行，不能删除当前手工验收数据来满足脚本空库要求。
