# 阶段 3：双设备验收步骤与记录

本阶段只实现时段操作及晚间模板调整，不实现阶段 4。以下是待真实执行的步骤，不是已通过声明；本地自动化证据见 [CHECKS_STAGE3.md](CHECKS_STAGE3.md)。阶段 1 D01～D11、阶段 2 v1 完整界面迁移／自然会话过期／未完成安卓专项保留原状态。

## 准备与升级

1. 保留阶段 2 完整 v2 备份。在隔离 Supabase 项目先演练，只执行新增 `202610210001_stage3.sql`，之后部署本 PR 的 0.3.0 前端；不重跑阶段 1/2 已应用迁移。空项目按顺序安装三份迁移。
2. 手机和电脑打开同一个 HTTPS 网址、使用同一个 Supabase Auth 账号。记录部署 SHA、迁移、实际日期（Asia/Shanghai）、手机／系统／浏览器、电脑／浏览器。不要从旧阶段复制环境信息当作本次结果。
3. 在任务池准备“物理 → 理论力学”，总量 40、初始 8、位置 `2.1.1`。以一段空白日期为本次虚构测试数据范围；以下日期可用 2026-11-03。
4. 手机默认日视图，电脑默认周视图。新模板每天 11 块，晚间 90/60/60，白天不变；预算始终“未设置”，实际记录“尚未开放”。

## 1. 09:00–11:00 合并再拆分

1. 手机分别在 09:00–10:00 和 10:00–11:00 安排理论力学，范围 `2.1～2.3`、备注“阅读例题”。每次等待云端确认。电脑获取最新数据。
2. 手机点“选择时段合并”，点击这两个安排，再点“合并所选安排”。核对任务、范围和备注，勾选最终确认，点“确认合并到云端”。成功后只有一个跨行的 **09:00–11:00、120 分钟** 日程；电脑刷新一致。
3. 电脑编辑此块，勾选“拆分时复制计划范围和备注到每个基础时段”，点“拆分恢复基础时段”并确认。手机刷新应看到两个 60 分钟块，任务 ID 相同，文字各一份，总计仍 120。
4. 再合并、拆分一次，不勾选复制文字：范围／备注只在首块，其余为空；任务关联保留。任务初始量仍为 8、位置仍为 `2.1.1`，没有实际投入增加。
5. 合并块可再次与真实相邻的第三块合并。也可从空白格新建并选择“结束基础时段”创建连续长块。

## 2. 晚间 210 分钟与历史快照

1. 手机依次在 **18:30–20:00、20:00–21:00、21:00–22:00** 安排临时报告，分别应为 90、60、60 分钟，临时事项不进入任务池。
2. 选择三块、核对并确认合并，显示 **18:30–22:00、210 分钟**（3.5 小时）；电脑刷新看到一个日程。拆分后恢复 90/60/60，总分钟不变。
3. 有阶段 2 历史安排时，旧模板仍显示 18:30–20:15／20:15–22:00 各 105；日历必要时显示 20:15 分界，两张卡片均可见、可编辑。旧两块合并仍是 210，拆分仍恢复旧 105+105，不偷偷改为新分钟。
4. 新建 v2 20:00–21:00 与旧 v1 18:30–20:15 有真实重叠时必须失败，不能通过不同模板绕过占用。请在隔离副本上验证，不改写原始备份。

## 3. 连续性与不同内容选择

1. 安排 11:00–12:00 与 13:00–14:00，选择合并应提示不能跨午休。16:00–17:00 与 18:30–20:00 同样拒绝。跨日、跳过空格的两块也不能合并。失败前后日程、分钟、版本与占位不变。
2. 在相邻两格放不同长期任务／临时事项，以及不同范围、备注。合并界面必须同时展示源内容，最终提交起初不可用。
3. 分别明确选择“任务”“计划范围”“备注”的来源，或选择手动填写并编辑下方最终内容，再勾选确认。电脑获取后核对最终三项；任务仍按稳定 ID 关联。未完成明确选择不得提交。
4. 将某块合并日程移到另一空闲日期，旧日期应完整释放、新日期完整占用。再尝试移到与其他块部分重叠的位置：整笔失败，原日程／占位不变。移除合并块后所有基础时段释放，任务池不变。

## 4. 双设备竞争与旧表单

1. 两端获取同一版本并对同一组相邻安排打开合并表单，同时提交：只能一方成功，另一方提示版本冲突并保留输入；刷新后只见一个结果，没有残留源日程。
2. 两端打开同一合并块，一端拆分，另一端移动／移除或修改后保存。只能一个旧版本操作成功；失败方输入保留，没有部分拆分、重复占位或幽灵占位。
3. 两端同时在同一天同一空基础时段创建日程；也尝试新长块与已有单块部分重叠。最多一项占用。真实 API 并发另由隔离脚本验证。
4. 手机改范围并保存，电脑旧表单提交必须冲突。电脑“获取最新数据”后仍保留旧输入，不能自动提高表单版本；核对最新卡片，明确“已核对，将日程输入应用到最新版本”才可继续。合并表单重新核对后还需再次勾选最终内容确认。
5. 合并来源已被另一端移除时，旧合并表单不可重新应用；可复制文字后取消再选择。备份恢复后的旧表单同样不能覆盖新版本。

## 5. 断网与响应丢失

1. 两端先取到数据。手机断网并取数：显示失败，原日程保留并提示可能过期，最近成功获取时间不变，不冒充空库或误显未登录。
2. 在合并表单完成三个内容选择后断网提交：不得显示成功，源日程不被本地乐观删除，文字保留。如果结果未知，输入锁定、原 requestId 保留；联网后点“确认并重试原请求”。
3. 在隔离 API 或本地浏览器检查中模拟“数据库已提交、响应丢失”，分别执行合并和拆分。按原 requestId 确认／重试后，revision 只增加一次、源或结果数量正确、拆分 UUID 不重复新增。一般手机断网不能替代这一证明。
4. 安卓断网切后台返回、恢复联网后取数；真实会话失效时停止业务请求、隐藏数据，同账号重登后保留原输入／未知请求供确认。退出会清除内存草稿；关闭页面不是离线队列，重开须取数核对，不盲目新建。
5. 自然会话过期／续期和未完成安卓专项仍待单独实测记录，不因模拟 JWT／网络测试通过而勾为通过。

## 6. 完整 v3 备份恢复与阶段 2 v2 迁移

1. 同时保留长期任务合并块、临时报告、基础单块及可用的历史模板日程。导出完整 JSON，核对 schemaVersion=3，分类、任务（含归档）、设置和全部日程完整；日程含 UUID、taskId、date、slotIds、slotTemplateVersion、startMinute、endMinute、范围和备注。无密码、token、key、owner_id 或内部回执。
2. 电脑打开旧表单；手机修改／移除一些安排后选择该 v3 文件。预检显示数量，勾选完整替换确认，再恢复。电脑获取后所有日程与分钟一致，原旧表单不能覆盖。恢复后尝试占用某合并块的中间格应拒绝，证明占位也恢复。
3. 预检后让电脑先保存，再由手机确认恢复：应版本冲突并要求重新预检。文件副本中制造部分时段重叠、跨模板重叠、缺失任务、重复 ID、伪造分钟或未来版本，应拒绝且云端不变。
4. 保留当前 v3 文件，再选择真正有效的阶段 2 v2 备份。预览应显示 **v2→v3** 和原日程数量；确认恢复后原 UUID、taskId、日期、105 分钟历史快照及任务初始量均保留。两端核对。不应出现“旧备份无日程”的提示，也不应自动重排为 90/60/60。
5. 最后可恢复之前的 v3 找回本次合并安排。有效 v1／约定 v0 仍支持，预检明确说明其日程为 0、完整恢复会清空当前日程；损坏／伪造旧版本拒绝。阶段 2 中未验证的真实 v1 完整界面迁移仍未自动通过。
6. 在隔离项目执行 `npm run test:integration`，保存退出码和脱敏输出。脚本覆盖 Auth、全部表权限、多连接竞争、失败回滚、回执与迁移输出恢复；不能在日常账号执行破坏性测试。
