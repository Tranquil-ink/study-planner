## 启动

固定 Node.js **24.19.0 LTS**、npm **11.9.0**；不混用包管理器，不随意更新依赖。

```bash
nvm install
nvm use
npm ci
cp .env.example .env.local
# 按 docs/SUPABASE.md 创建项目、应用迁移、创建账号并填写公开配置
npm run dev
```

Windows 无 nvm 时安装相同版本 Node/npm，复制 `.env.example` 为 `.env.local` 后执行 npm 命令。打开 Vite 输出的网址（通常 localhost:5173）；手机不能使用电脑的 localhost，双设备需配置可达 HTTPS 验收网址。修改 `.env.local` 后重启服务。

只允许 `VITE_SUPABASE_URL`、`VITE_SUPABASE_PUBLISHABLE_KEY` 为前端配置。后者可使用 publishable 或旧 anon key，绝不能使用 service_role/secret key。凭据与个人备份不提交 Git。

数据库安装、关闭注册、账号恢复、网络允许列表与真实集成测试配置详见 [docs/SUPABASE.md](docs/SUPABASE.md)。用户已建立 Cloudflare HTTPS 测试站点；正式 GitHub Pages 配置仍属于阶段 7。

## 阶段 5A 升级与使用

先在阶段 4 前端导出并保留 v4 JSON；按 [增量升级说明](docs/SUPABASE.md#阶段-5a-增量升级) 执行 **`202611010001_stage5a.sql`**，再部署 0.5.0 前端并重新打开两端。空项目依次应用全部五份迁移。旧业务数据与回执保留，账号 revision +1，旧恢复请求不能误清空新实体。

1. 在“待办”点击“收集一次性待办”，输入名称即可保存；估时可留空。在“全部待办”查看未指定周的事项、编辑或归档。
2. 在“本周计划”选择历史／未来执行周，先编辑常规可用时间模板。勾选每天准备学习的时段；模板用于新周，已保存周不被回写。
3. “编辑本周计划”从任务池或待办加入重点。选择主要目标，填写预计／目标分钟、进度新增量、重要程度和截止日期。同任务同周不能重复加入，跨周仍引用同一任务。
4. 查看可用、计划、已排、实际四类时间。可用20小时、计划24小时会提示超出4小时但允许保存；也可在本周例外中调整容量，不改变模板。日历底色显示可用时间，额外安排单列。
5. 未勾选确认时保存草稿；勾选“确认初始计划”留存初始目标。后续修改或取消条目保留历史，页面可展开每个版本；不改写实际投入和进度。
6. 可勾选下周带入；切到下一周点击“从上周带入已勾选的草稿”，核对目标／估时后自行保存、确认。不会自动确认或排程；剩余工作结转属于5B。
7. 另一设备主动获取最新数据。旧表单保持原版本和输入，核对后显式重新应用；保存结果未知时确认并重试原请求。
8. 完整备份 **v5** 包含全部旧实体、待办、周计划（初始目标、版本历史、各周容量）与可用模板。v0～v4严格迁移，新规划集合为空；恢复前明确提示会清空已有规划历史，需先备份。

当前提供周总体已排／实际分钟与任务预算参照；周条目到日历的分次排程、进度分配、自动完成状态和一次性完成确认在5B实施，复盘报表在6A实施。

## 阶段 4 历史交付功能

以下为阶段4原有升级路径及功能说明；已升级至阶段4的项目只需执行上述5A新增迁移。


已完成阶段 3 的项目：先导出保留 v3 JSON，按 [阶段 4 升级说明](docs/SUPABASE.md#阶段-4-增量升级) **只执行新增 `202610250001_stage4.sql`**，再部署 0.4.0 前端，两端重新打开。空项目依次应用四份迁移。原任务、日程时间快照和请求回执保留，已有账号 revision +1。

- **合并内容选择简化**：内容不同时只选一个原日程，任务、计划范围和备注整体沿用它，预览后确认。不再分别选择范围或备注；时段、合并／拆分、午休限制及历史模板规则保留。
- 日历的“补记实际学习”可创建无计划记录；编辑已有日程后点“记录此日程的实际学习”可关联已保存计划。实际分钟数留空待填，不把计划分钟数当成实际。
- 填写实际日期、任务／临时事项、正整数分钟数、**本次新增完成量（不是累计量）**、实际位置与备注。允许超出计划时间、有投入但新增量为 0；临时事项不显示数值进度。归档任务可补记。
- 修改、删除同一条实际记录后重新汇总：初始 8，新增 1.5 后为 9.5，改为 1 后为 9，删除后为 8。表单展示保存后累计预览；初始量加全部记录不得超过已设总量，修改任务总量／初始量和恢复也检查。
- 任务池可选择统计截止日，累计量、实际分钟和位置只使用该日及之前记录。最近非空位置按业务日期、同日稳定创建顺序确定；编辑历史记录不会覆盖更晚位置。
- 日程卡片标记是否已有实际记录；周汇总分开显示已排和实际分钟数，预算仍为“未设置”。实际时间按记录日期汇总，包含无计划补记。
- 有实际记录关联的日程不能合并／拆分，仍可编辑实际。移动日程不移动实际日期；**更换任务或移除日程会保留实际记录，并解除日程关联**（本轮用户确认）。实际记录也可手动解除或重选匹配任务的日程。
- 每次记录使用稳定 UUID 和服务器创建顺序；修改不重排。沿用账号锁、版本、requestId、失败草稿保留与原请求确认重试，拒绝过期编辑，不重复累计。所有写入通过统一 Repository 和受控 RPC。
- 完整备份 **v4** 包含分类、任务、日程时间快照、实际记录及稳定创建顺序、设置。支持严格校验 v3/v2/v1/v0 后迁移；旧备份没有实际记录，恢复预检明确警告会清空当前实际记录。恢复原子替换，出错旧数据不变。
- 手机日视图／电脑周视图、11 个基础时段、晚间 90/60/60、历史 105 分钟、触控合并拆分、任务分类色、登录及主动获取等既有功能保留。

## 检查命令

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 开发服务 |
| `npm run typecheck` | 应用、配置、测试和集成脚本类型检查 |
| `npm run lint` | 代码检查，警告视为失败 |
| `npm run test -- --run` | 数量/备份、客户端失败、迁移在本地 PostgreSQL 引擎上的测试 |
| `npm run test:integration` | 指定真实 Supabase 隔离项目，检查 Auth、RLS、并发、幂等与恢复；缺配置退出码 2 |
| `npm run check:browser` | 可重跑的浏览器风险检查：模拟 Auth/HTTP + 本地 PostgreSQL，不替代云端验收 |
| `npm run build` | 检查类型并构建到 dist/ |
| `npm run preview` | 预览已构建的静态网页，通常 localhost:4173 |

先 build 再 preview，不直接双击 HTML。本地测试中的 PGlite 仅为开发依赖，不进入生产包，不是应用存储方案。真实集成与安卓手动验收必须另外执行。阶段 7 再汇总正式 E2E/CI。阶段 1～5A 的相关风险使用独立浏览器检查，运行前安装浏览器：

```bash
npx playwright install chromium
npm run check:browser
```

已有系统 Chromium 时可设置 `CHROMIUM_EXECUTABLE_PATH` 指向它（本次 Linux 用 `/usr/bin/chromium`）。脚本自行启动 5174 端口的 Vite，只在测试内拦截请求并使用虚构样例，不连接真实 Supabase；产物写到已忽略的 work/。环境与范围见 CHECKS。

## 双设备快速验收

1. 按 Supabase 文档建好测试项目并配置同一 HTTPS 网页，手机与电脑登录同一个账号。
2. 手机创建“物理 → 理论力学”，总量 40、初始 8、位置 `2.1.1`，等待云端确认；电脑获取最新数据应见同一内容。
3. 电脑修改备注，手机获取最新数据应一致；归档后勾选显示归档仍可查看。清除一个设备的测试网站数据，重新登录仍能取回已确认记录。
4. 两端同时打开旧表单，先保存者成功，后保存者提示冲突且保留输入；刷新后核对并明确重新应用。
5. 导出完整 JSON，修改后恢复；预检展示两份数据的数量并要求确认替换。另一设备刷新见恢复结果，旧表单必须冲突。
6. 断网取数不冒充空库，保存失败不显示成功；联网后确认原请求、幂等重试。执行真实集成脚本检查权限、响应丢失与回滚。

## 数据规则和限制

详细契约见 [docs/DATA_MODEL.md](docs/DATA_MODEL.md)。进度为最多 9 位整数、6 位小数的非负精确数量，超精度拒绝、不截断；初始量不能超过总量。备份 v1/v2/v3/v4/v5 用十进制字符串；v0 是明确约定的测试迁移格式，未得到真实旧 IndexedDB 样本，不支持猜测格式或跨 origin 直接读取。

阶段 5A 已实现周目标与预算；5B 执行联动、6A 复盘、6B 周期与预测、7 正式发布尚未开放。当前已实现实际记录、累计进度及周实际分钟汇总，没有学习速度或预计完成日期。分类/任务采用归档，不提供硬删除。设置固定中国时区与日期格式。

未知请求只保留在当前页内；关闭/刷新页面会丢失草稿和内存请求信息，重新打开后需获取云端并核对，不能盲目重复创建。备份导入上限 10 MiB，导出没有分页截断；超过此个人使用规模须先扩展恢复能力。恢复重建服务器审计时间但保留 UUID 和业务内容。
